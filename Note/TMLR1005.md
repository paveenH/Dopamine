# TMLR

## 核心问题

**核心问题：** RSN steering 如何改变 commitment-related behavior，以及为什么其推理收益随模型、任务和接口变化？

以三类证据组织论文：行为干预效应、推理响应、接口依赖。Dopamine-inspired hypothesis 是研究动机；dopamine 的计算或行为对应及其生物学边界放在讨论中。论文不预设所有条件都有准确率收益，也不预设统一的剂量曲线、最优 α 或普适的 Role controller。

**首选工作标题：**

> Role-Sensitive Steering Modulates Commitment and Reasoning Across Models and Interfaces

标题和贡献在 claim–evidence table 完成后再复核。

## 证据层级与写作规则

每个结果段和图注应说明证据属于哪一层；不同层级不能互相替代。

| 标签 | 证据层级 | 可支持的写法 | 不可越过的边界 |
|---|---|---|---|
| **O：直接观察** | 文本、选择、时序、准确率或隐藏状态的观测及其统计比较 | 「在该模型、任务和接口下观察到……」 | 可见输出顺序不等于内部 commitment；不显著不等于等价、知识不变或无效应 |
| **I：因果干预** | 对 RSN 方向施加 α steering 后，相对同一实验内 α=0 的变化 | 「steering 改变了该测量指标」 | 不自动证明方向特异性、跨条件通用性或下游因果链；raw α 不是跨模型等效剂量 |
| **M：机制解释** | commitment、entry–decode dynamics 或 baseline state 对结果模式的解释 | 「结果与……解释一致／支持……解释」 | commitment 与 accuracy 的共同变化不是已证明的因果中介；避免将解释写成已识别机制 |
| **A：dopamine 类比** | 对计算功能或行为模式的类比 | 「具有有限的功能／计算类比」 | 不声称生物同源、神经递质浓度对应、受体机制或脑区实现 |

统一边界：

- 将「baseline state 决定收益」写为「结果支持 **baseline-state-dependent interpretation**」。这是对模式的解释，不是已经验证的调节因果模型。
- 将「Chat/post-training 重设状态」拆开：Bare/Chat 接口条件下的输出与 steering 响应差异有结果支持；post-training 是否造成该状态差异仍**待 Base–Instruct 对照验证**。
- 准确率未显著变化只报告为「未检测到显著差异」（附效应量、区间及检验口径）；不写成知识保持不变、没有代价或统计等价。
- commitment 指标与 accuracy 同向变化、相关或预测时，标记为解释性关系，不能称作 mediation 或已证明的中介链。
- 分开报告被测行为、测量定义、模型/任务/接口与可用分母。不同接口、prompt、mask 或任务口径不可在没有匹配设计时当作同一条件。

## Task-entry gain 与 adaptive calibration

- 保留 **task-entry gain** 作为操作性定义，明确具体读数（如 `G_prefill` / `Z_prefill`）、提取位置、mask 与模型内参照。
- α 与 `G_prefill` 的近线性关系主要是 **manipulation check**。部分线性来自注入方向和投影读数的共同设计；不能把它单独当作 RSN 方向特异性、独立机制证据或跨模型等量操控的证明。
- 解释重点放在 **entry–decode decoupling**、后续可观察的 commitment-related behavior，以及模型特定的非线性 reasoning response。Llama 的不对称峰形与高剂量塌陷、Qwen 的高剂量平台应分别按各自结果文档表述；raw α 与跨模型投影数值不可直接比较。
- 「adaptive calibration」作为假设或讨论框架使用。除非有证据表明系统能按状态自动选择 α 或根据反馈校准，否则不把它写成已实现的控制能力。已测试的 closed-loop 波形控制没有建立准确率控制能力。

## 贡献草案

以下是待由 claim–evidence table 支持和收缩的贡献，不是预先锁定的结论：

1. **行为干预：** RSN steering 改变若干任务特定的 engagement / commitment 相关读数；以 Betting 与 CGT 为优先证据，并逐项注明哪些变化是干预效应、哪些是观察指标。
2. **行为与答题表现的关系：** 在部分条件下，行为读数变化与准确率变化解离。准确率差异不显著不得改写为等价或知识保持。
3. **推理响应的条件依赖：** reasoning response 随模型、任务和接口变化；完整剂量曲线、targeted dose comparisons 与跨任务边界应分别标明。
4. **解释与边界：** 轨迹和表示分析为 entry–decode decoupling、commitment dynamics 与接口依赖提供辅助解释，同时明确其观察性或 readout 限制。

**相较父 RSN 论文的增量（待逐项核对 ACLARR §6.1 与本文证据）：** 父论文提出 RSN 与 confidence steering，并提出「Digital Dopamine」假说。本文规划的新增重点是跨任务的行为干预证据、commitment-related behavior 与 reasoning response 的并置分析、模型特定剂量响应，以及 Bare/Chat 接口依赖和相应边界。准确增量、可复用结果与重叠文本/图表须在写稿前核对；不得将父论文已经建立的 RSN 定义或假说重新包装为本文新贡献。

## 暂定文章结构

### 1. Introduction

提出核心问题与 dopamine-inspired 动机；简述父 RSN 论文与本文增量。将本文定位为检验 RSN steering 对行为和推理响应的影响及其条件边界，不预告已证实的 dopamine 机制或统一 calibration controller。

### 2. Intervention, Measures, and Experimental Setup

定义 RSN steering 与 α、模型/任务/接口、task-entry gain 的操作性测量、主要行为和答题读数、统计口径。说明 raw α 的不可通约性、有效分母和主要限制。读数命名和分析口径以权威文档为准。

### 3. Behavioral Effects and Reasoning Responses

先呈现 Betting 与 CGT 的行为干预，再呈现 Llama/Qwen dose response 与 Bare 条件下的 reasoning 结果。区分直接 steering 对行为指标的效应、准确率结果与两者之间的解释性关系。IGT 与 HaluEval 仅在它们支持明确的 task boundary 或限制 claim 时纳入。

### 4. Commitment Dynamics and Interface Dependence

呈现 entry–decode decoupling、可见答案形成/提交行为及其与准确率的解释性关系；随后比较 Bare、Native Chat 与 Matched-Anchor 的具体差异。明确接口效应有证据支持；post-training 来源解释仍待 Base–Instruct 对照。Mathed-Anchor 的范围与接口不可混同，按原文名称 **Matched-Anchor** 使用。

### 5. Specificity, Boundaries, and Discussion

按需要纳入 specificity controls、跨任务边界、Bandit、closed-loop、manifold 与 dopamine-inspired interpretation。只有当某项证据限定或支持一条明确 claim 时才放入主文；其余移入补充材料或不纳入。讨论区分 RSN causal intervention、readout specificity、结构相关与 dopamine 类比。

## 实验素材的暂定位置

| 素材 | 暂定用途 | 写入前检查 |
|---|---|---|
| Betting | 行为干预主证据；行为读数与 accuracy 解离的候选例子 | α、模型、任务、有效样本、配对检验及 Holm family；不显著 accuracy 只称未检测到差异 |
| CGT / CGT-Sequential | 风险/接受时机等任务特定行为补强 | 分开任务版本、模型与通过有效性 gate 的剂量；不把局部有效范围称为完整跨模型复现 |
| Llama/Qwen dose response | 推理响应的主要跨模型素材 | `first_acc` 与可见 commitment/output 指标分开；模型内剂量与跨模型比较分开；不声称 mediation |
| Bare/Native Chat/Matched-Anchor | 接口依赖与 prompt/interface 边界 | 不把跨接口描述比较当成样本级因果对照；区分 Native Chat 与 Matched-Anchor |
| IGT | 仅在具体结果支持清楚的行为边界时纳入 | 汇报 learning-independent 指标、退化模式与模型差异；完整协议史不进主文 |
| HaluEval | challenge-threshold 等 task-specific boundary 候选 | 核对操纵、样本与实际支持的 claim；避免把单一 challenge 指标推广为通用 engagement |
| Bandit | 边界或识别/行动限制 | PV10/PV11 等状态按 `Bandit.md` 与 `CLAUDE.md` 冻结措辞；不恢复已作废协议或已关闭主张 |
| Closed-loop | 限制 adaptive-control claim 的负/边界证据 | 波形形状控制不等于准确率控制；避免写成已实现反馈校准 |
| Manifold | 对表示几何解释的边界证据 | 只陈述冻结结论；不把 last-prefill geometry 写成 commitment 的充分解释 |
| Role–Confidence | 辅助表示与功能关系证据 | 区分共享结构、不同功能剂量响应与因果 steering specificity；避免轴等价主张 |
| Role–Chat | 辅助接口表示关系 | dense mean direction、稀疏坐标、transition-subspace 分开；结构关系不等于共享因果机制 |
| GRSN/AGRSN | prompt 条件性 Role geometry 的辅助证据 | 低相似度只限制当前测试 prompt 下的共享方向主张，不能证明所有条件下不存在稳定 Role controller；完整 Metrics 1–5 优先放补充材料 |

## 主图候选 storyboard

由 claim–evidence table 决定是否保留、合并、拆分或改为补充图。每个 panel 标示模型、任务、接口、干预条件、分母和证据层级。

1. **问题与实验地图：** 核心问题及行为、推理、接口三类证据；概念箭头只表示待检验关系。
2. **行为干预：** Betting 与 CGT 的主要 engagement / commitment 相关指标，并并列报告对应 accuracy 检验及区间。
3. **推理剂量响应：** Llama 与 Qwen 按各自模型和任务呈现完整可引用曲线；不把 raw α 当作共同横轴剂量。
4. **入口与后续行为：** `G_prefill` manipulation check、entry–decode 响应及 commitment-related 输出分开呈现；区分 steering 的干预效应与观察性解释关系。
5. **接口依赖：** Bare、Native Chat 与 Matched-Anchor 按可比较设计呈现；接口差异与 post-training 来源解释分开。
6. **证据边界：** 跨任务素材及表示/控制证据，仅纳入能限定表中具体 claim 的内容。

图中直接因果干预效应与解释性关系使用不同图形编码；不得用连续实线箭头暗示从 gain 到 commitment 再到 accuracy 的完整因果链已被证明。

## 下一步工作顺序

1. **核对核心 claims、结果口径与父论文增量。** 逐条回到 `CLAUDE.md`、权威结果文档和父论文 `ACLARR/main.tex`；确认冻结状态、分母、统计校正、接口定义与可主张的新增内容。
2. **建立并填写 claim–evidence table，再发展候选主图。** 表格先于图；六图 storyboard 保持可调整。
3. **写出完整初稿，定位最关键的证据缺口。** 不等待所有可能的补充实验；用稿件中实际保留的 claim 决定缺口优先级。
4. **若方向特异性仍是关键缺口，优先设计 norm-matched random/orthogonal causal steering controls。** 这不同于对既有 hidden states 做 offline re-projection；后者是 readout control，不能代替重新注入并生成的因果对照。
5. **依保留的 claim 决定是否补 Base–Instruct 或 held-out state transfer。** Base–Instruct 只在稿件保留 post-training 来源解释时考虑；held-out state transfer 只在稿件需要跨状态因果迁移主张时考虑。

额外实验是否必要，由写成的稿件主张和其证据缺口决定。当前计划不把额外实验统一设为前置条件，也不预先保证特定投稿路线。
