
## 第一优先：统一跨模型核心指标

这些都是数字答案任务，最适合在 Llama/Qwen 上统一重算：

1. **GSM8K**
   - Llama：No-CoT、CoT
   - Qwen：No-CoT、CoT
   - 指标：`first_acc`、`last_acc`、`early_candidate_rate`、`reason_first_rate`、`pre/post_candidate_chars`、valid submission

2. **MATH**
   - Llama：No-CoT、CoT
   - Qwen：No-CoT、CoT
   - 同上，但不要把 `boxed position` 当主要 commitment 指标。

3. **GSM-Hard**
   - 两个模型、No-CoT/CoT
   - 与 GSM8K 使用完全相同的指标，适合检验跨难度迁移。

4. **GSM-Symbolic**
   - 两个模型、No-CoT/CoT
   - 当前已有 `ec`、`reason_first`、`posN`，需要与 GSM8K/MATH 统一命名、分母和统计方式。

这是最重要的一组，完成后就能形成真正一致的 Llama–Qwen 主行为分析。

## 第二优先：可以整理，但要保留任务特性

5. **BBH Object Counting**
   - 数字输出，可以使用统一的 candidate-timing 指标。
   - 但要同时报告 degenerate/loop，避免把格式退化误读为行为改善。

6. **CRUXEval-O**
   - Bare 与 Chat 应分开。
   - 可整理 `early_candidate`、pre/post-marker length、valid submission、degenerate/truncation。
   - Python literal 输出和 marker 规则特殊，不能直接照搬 GSM8K 数字提取器。

7. **FinQA**
   - 可以统一 first/last、candidate timing 和 stopping。
   - 但必须突出它是自定义数字答案评分，不是官方 program execution。
   - Llama 的严重 loop/truncation 应作为解释前提。

## 第三优先：需要任务专属指标，不宜强行统一

8. **LogiQA 2.0**
   - 答案是 A–D，现有数字版 `early_candidate_rate` 不适用。
   - 应改用 task-native 指标，例如：
     - `native_answer_first_rate`
     - valid option submission
     - pre/post-answer characters
     - first–last option change

9. **ProofWriter-OWA**
   - 输出是 True/False/Unknown，重点应是：
     - valid submission
     - no-answer rate
     - conditional accuracy
     - multiple-answer/first–last disagreement
     - loop/truncation
   - 不建议强行套数字 candidate detector。

10. **ZebraLogic-Easy**
    - JSON/结构化答案，核心是：
      - valid JSON / complete answer rate
      - no-answer rate
      - puzzle accuracy
      - truncation
    - 不适合直接与 GSM8K 的 commitment timing 横比。

另外，两组可以暂时不进入统一整理：

- **Persona 实验**：保留为模型特异性的文本内容分析。
- **Willingness / confidence 自评**：作为失败的 manipulation check 简短保留，不必继续扩充指标。

建议实际执行顺序是：

> GSM8K → MATH → GSM-Hard → GSM-Symbolic → BBH → CRUXEval/FinQA → LogiQA/ProofWriter/ZebraLogic

前四个建立统一主指标体系；后面的任务主要用于检验适用边界，不必追求所有任务拥有完全相同的指标。

## Llama3.1-8B-Instruct — GSM8K

| 指标                    | 含义                                 |
| --------------------- | ---------------------------------- |
| `α`                   | RSN 干预强度；不同模型间不能直接比较数值大小。          |
| `n`                   | 该条件下的样本数。                          |
| `first_acc`           | 按第一次正式答案判断的准确率，主要性能指标。             |
| `last_acc`            | 按最后一次正式答案判断的准确率，用于观察答案修订。          |
| `fixed_n`             | 第一次答错、最后一次改对的样本数。                  |
| `broke_n`             | 第一次答对、最后一次改错的样本数。                  |
| `valid_sub_rate`      | 能解析出正式答案标记的比例。                     |
| `cond_acc`            | 只在存在有效正式答案的样本中计算的准确率。              |
| `early_cand_rate`     | 输出开头很早就出现答案候选的比例。                  |
| `cand_coverage`       | 能定位到第一个答案候选的样本比例。指标可计算性的覆盖率/质量检查指标 |
| `reason_first_rate` | 首次答案候选前出现 `=`、`Step 1` 或编号步骤等推理文本的比例；属于表面文本代理指标。 |
| `pre_cand_chars_med`  | 首个答案候选之前的字符数中位数。                   |
| `post_cand_chars_med` | 首个答案候选之后继续生成的字符数中位数。               |
| `posN_med`            | 正式答案标记在全文中的归一化位置中位数，范围为 0–1。       |
| `multi_marker_rate`   | 同一输出中出现多个正式答案标记的比例。                |

> **备注：**“答案候选（candidate）”与“正式答案标记（marker）”不是同一事件。candidate 是输出中最早出现的答案形态数值或表达式，例如开头的裸数字、等号右侧结果或 “the answer is …” 后的值；它不要求与正确答案匹配，也可能是中间结果。marker 则是 `####`（GSM8K）或 `\boxed{}`（MATH）等正式提交格式。因此，candidate 通常用于分析答案形成顺序，`posN_med` 用于分析正式提交位置。
