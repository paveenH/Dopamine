## Position

## Fixed design
| | Llama-3.1-8B-Instruct | Qwen2.5-7B-Instruct |
|---|---|---|
| alpha | 0, −6 | 0, +8 |
| band | [11,20) (L=9) | [16,22) (L=6) |
| mask | `mask/llama3_non_logits/nmd_0.5_11_20_8B.npy` | `mask/qwen2.5_non_logits/nmd_0.5_16_22_7B.npy` |
| expected `steering_fires` (α≠0 / α=0) | 2700 / 0 | 1800 / 0 |

Common: the 300 items of `finqa_formal.json` in file order; 0-shot, explicit CoT, neutral; greedy
(temperature 0, top_p 1); `max_new_tokens=512`; batch 8; `prefill_only=True`, `prefill_tail_len=1`. Each model's two
cells are generated by one process (one model load, one GPU). Only these four cells; no further doses.

## Prompt and injection
User message = `finqa/prompt_finqa.FINQA_TEMPLATE` rendered unchanged (CoT line, answer-format sentence, trailing
`Answer: `). It is the only message: no system message is written, none appended after the template. Wrapping:
`tokenizer.apply_chat_template(..., tokenize=False, add_generation_prompt=True)`, duplicated BOS stripped.
Injection site = the last token of the model's own assistant header, **read from the real tokenizer for all
prompts** (must be uniform, exactly one BOS); no artificial anchor. The tokenizer's own template behaviour is kept:
the Llama-3.1 template trims user content (so the trailing space of `Answer: ` may not survive) and the Qwen2.5
template may add its default system turn. The wrapped-prompt sha256 in each cell's meta records what was fed.

## Stages
`run` (300 items, both alphas, one model load) then `eval` (CPU, offline; the only stage that reads gold).
No separate check/smoke stage.

Existing files are skipped only after full validation (protocol, alpha, band, generation settings, mask / prompt /
chat-template / data-file hashes, model repo id, per-item `sample_id`/`id`/`question` order, fire count, row
completeness, stored diagnostics re-derived from the text); any mismatch aborts, never overwrites. Writes are
atomic. Provenance recorded: host, `CUDA_VISIBLE_DEVICES`, device names, sharding, torch/transformers/numpy
versions, git commit (+dirty).

## Scoring and statistics
Reuse `finqa_scoring.py`: MAIN `first_acc` = first legal `#### <value>` over all 300 items (no legal marker =
incorrect); `last_acc` sensitivity; no fallback, no looser scoring. Reported per cell: valid-submission rate,
conditional accuracy (valid subset), repeat submission, loop, truncation, natural-EOS, lengths; loop and truncation
split by whether a legal answer was submitted (a loop after the first answer does not remove the scorable item;
failures before any answer count as incorrect). **Custom direct-numeric evaluator, not the official FinQA
program/DSL execution scorer.**

Two contrasts: Llama −6 vs 0, Qwen +8 vs 0, paired by item, exact McNemar, W→C / C→W counts, question-paired
bootstrap 95% CI (B=10000, seed 0), **Holm m=2** (own family, separate from `finqa-v0`'s m=3). Bare-vs-Chat is a
descriptive side-by-side only; no interaction test, no claim that the interface changes the steering effect.

## Exploratory
Early-candidate (`earlycand-v1`, optional, unchanged) was never extended to FinQA surface forms. The evaluator also
classifies each reply's first line by format (bare number, currency, percent, unit, `Answer:`-style, question
restatement, reasoning opener, long, other) and lists detector misses on number-like first lines, with a
format-robust "answer-shaped first line" rate next to the detector rate. Visible-order description only; unadjusted,
outside Holm, not internal commitment.
