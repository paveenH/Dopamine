# Bandit protocol internals pv6–pv11 (⛔ CLOSED)

Split out of `CLAUDE.md` on 2026-09-02 to shrink the always-loaded context. The
Bandit line is CLOSED per the PV11 pre-registered termination rule: **five**
intervention classes (Stage-1 α, choice history, Beta calculator, competitor cue,
controlled evidence state) each raised the model's *recognition* of uncertainty
without moving *acquisition*. Do not re-run, extend seeds, or iterate the prompt.

`CLAUDE.md` keeps the closure verdict, the pre-2026-07-28 VOID warning, and the
four facts later protocols inherit from pv1–pv5. Design + literature +
result tables: `AdaBandit.md` §1.3–§5. Local check commands:
`docs/LOCAL_CHECKS_ARCHIVE.md`.

Everything below is byte-identical to what stood in `CLAUDE.md`. Read it when
reusing a pv-era seed bank, gate rule, manifest or analyzer — several later
protocols (CGT-seq resume keys, PV10/PV11 口径) descend from these decisions.

  - **pv6 (F-reference) — the 2026-08 clean-slate redesign. SUPERSEDED as the main line (pv6 → pv7 → pv8 → pv9; see the pv9 bullet below), but still the source of the frozen competence gate, seed banks and algorithmic baselines every later protocol reuses.** Built after the pv5 verdict above; it does NOT continue that line, and nothing here is comparable to a pv1–pv5 cell (different environment, prompt, decoding, reward model, metrics, output tree, CSV schema). Design doc: `AdaBandit.md` §3 (renamed 2026-08-11 from `BanditExperiment_LiteratureReview.md`; older refs are stale) — read it before changing anything.
    - **Framing constraint on any two-scope result (settled 2026-08-05, binding):** a working "rationale −4 + action +4" combination would show RSN composes into an effective **phased division-of-labour controller** (階段分工控制器). It would **NOT** show that a single α has dopamine-like properties — the same episode uses two OPPOSITE directions. Keep that boundary in any writeup; the `both`-stage +4 data (margin down, non-novel churn up, persistence damaged) is *not* evidence of effective exploration, so do not assume action-side +4 will help Hard. The `{0,−4}×{0,+4}` 2×2 with `Δ_interaction = Y(−4,+4) − Y(−4,0) − Y(0,+4) + Y(0,0)` is the test, and it is **deferred**: it needs separate `rationale_alpha`/`action_alpha` parameters that do not exist yet, and `both(−4)` cannot serve as the `(−4,0)` cell.
    - **Framing (settled): this measures a CAPABILITY BOUNDARY and whether α moves it — not "make the task work".** Krishnamurthy et al. (NeurIPS 2024) found exactly ONE configuration that explores successfully across all their experiments (GPT-4 BSSĈ0); Llama2 failed its entire restricted sweep. A 7–8B model failing is the literature's expectation, so the competence gate is **pre-registered**, not chosen after seeing numbers.

    - **Environments** (μ\*=0.5+Δ/2, μ=0.5−Δ/2): `easy` K=4 .75/.25×3 T=100; `hard` K=5 .60/.40×4 T=100 — both competence-gate eligible. `native_floor` K=2 .70/.30 T=50 is a minimal stochastic-adaptation diagnostic ONLY: not a competence anchor, no B1 α experiment.
    - **Steering semantics: `--steering_scope {action,both}` (2026-08-04).** WHERE α lands inside a pass is frozen for both scopes — **once, at that pass's last prefill token, `prefill_only`, `tail_len=1`, decode never steered**. What the flag selects is WHICH passes get it. Stage 2 always injects at the tail of `Choice: Button`; the prompt must end there and nothing may follow it. Both stages temperature=0 (`generate` and `regenerate(prefill_only=True)` are both `do_sample=False` at temperature 0, so the scopes differ ONLY by hook registration).
      - `action` (the ORIGINAL pv6 semantics, now the mechanism **ABLATION**): Stage 1 gets no α — it calls `vc.generate`, which registers no hooks at all. Measures whether α moves the arm logits GIVEN a fixed rationale, i.e. an action readout.
      - `both` (the **B1 MAIN experiment**): Stage 1 is also steered, via `vc.regenerate(prefill_only=True, prefill_tail_len=1)`. α then reaches the choice by two routes — α→rationale text→action and α→action logits — which is what "does α move the whole information-seeking policy" requires. Do NOT widen this to decode-wide steering; prefill-only is the RSN convention and widening changes the intervention's definition.
      - **α=0 is identical under both scopes and must stay that way.** `diff_mtx is None` at α=0, so NO hook is registered in either pass — "unsteered" is deliberately not the same code path as "steered by zero". This is what makes the stored Track A α=0 cells reusable as B1's α=0 without a re-run; do not "unify" the two branches. Tests assert the trajectory and prompt chain are identical across scopes at α=0.
      - **Resume key**: the scope segment `sc{scope}{STEERING_SCOPE_VERSION}` (currently `scbothsv1`) is appended **only for a non-default scope** — the same asymmetry as `ut`, and for the same reason: stored Track A rows carry no scope segment, so emitting `scaction` would make every completed α=0 cell look unrun. `PROTOCOL_VERSION` stays `pv6`: scope changes the intervention, not the environment/prompt/scoring/seed bank/metrics. `STEERING_SCOPE_VERSION` exists so a LATER change to how `both` injects (tail>1, decode-wide, different anchor) cannot be mistaken for the same intervention.
      - **One `--ans_file` per α, always.** The pv6 detail JSON is named `bandit_pv6_{env}_{size}_{TOP}_{ls}_{le}.json` — no α and no scope in it — so two scopes in one dir overwrite each other; and `summary_{model}_{size}.csv` is per-`ans_file`, so parallel α processes sharing a dir would interleave appends and race the header migration. B1 dirs: `pv6_{easy,hard}_bare_both_{am4,ap4}`.
    - **`steering_fires` = OBSERVED injection evidence, in SITES.** `VicundaModel.steering_fire_count(reset=False)` counts one per **(steered layer, sequence, token position) that received a non-zero add** — deliberately NOT hook calls. `diff_matrices` is full-length (all 32 decoder layers, zero rows outside the band) and every layer registers a hook, and a K-candidate action pass is ONE batched forward, so a call-counter reports the same number for any layer count and any K (3200 for both stages on Llama3-8B) and proves nothing. With L steered layers: `regenerate(prefill_only, tail=t, B prompts) → L·B·t`; `regenerate_logits_teacher_forcing(K prompts) → L·K`. **L is 9, not 10, for the standard `11-20` band** — `utils.decoder_layer_range(11,20) = range(10,19)`, half-open like every other layer range in the repo (the "10 layers" figure elsewhere in this file is the HS-storage set: middle + final). **A pv6 episode at T=100 must therefore read `rationale=900` and `action=3600` (easy K=4) / `4500` (hard K=5)** — verified against the B1 smoke, which read exactly 900/3600. Deviations are diagnostic: 3200 = zero-rows counted (the site fix is not live), 100 = only one layer injecting, 0 = hook never fired; and `action == rationale` means the K factor is missing, so the counter cannot distinguish the two passes. The record carries both `steered_rationale` (configured intent) and `steering_fires` (observed) — **they can disagree only if there is a bug, which is why both exist**.
    - **Two-stage constrained choice ⇒ `invalid_rate` is STRUCTURALLY 0.** No free-text parser, no random fallback. A nonzero value means a bug, not a bad model.
    - **Chat mode: role structure is frozen** — user turn = task state only, assistant turn = the model's own rationale CONTINUED into the anchor (no `<|eot_id|>` between them). Feeding the rationale back inside the user turn would present the model's reasoning as if the environment said it. Chat also REQUIRES stripping the template's serialized BOS: `regenerate_logits_teacher_forcing` hardcodes `add_special_tokens=True` (llms.py:505), so without stripping the ids read `[128000, 128000, …]`. `audit_prompt_tokens` raises on double-BOS and on a prompt not ending at the anchor, and runs EVERY round.
    - **Per-arm reward tapes**, not one stream advanced per round: the n-th pull of arm *a* is the same latent outcome for every policy sharing a seed, so a cross-α difference cannot be reward luck on that arm.
    - **`bandit_pv6_baseline_manifest.json` is the FROZEN gate basis** (seed banks + bank_report + Random/Greedy/Oracle point estimates + bootstrap CIs), built before any model ran. `freeze_bandit_baseline.py --check` recomputes and diffs; a MISMATCH means the basis is not reproducible on that machine and **nothing downstream is citable**. Compare in round-tripped JSON form — `position_counts` has int keys and JSON has none.
    - **Seed banks are counterbalanced by a Latin-rectangle construction** (position × identity cross table, not just the two marginals): Easy 16/16 cells max repeat 2, Hard 20/20 distinct. A greedy first-come scan CANNOT reach this — do not "simplify" it back. Smoke seeds are disjoint from the formal bank; `run_bandit_reference.sh` hardcodes both and `test_bandit_reference.py` asserts they match the manifest (a copy can drift).
    - **Gate point estimates are seed-bank-sensitive at N=20** — Easy Greedy SuffFail moved 0.10→0.25 when the bank was fixed, and its bootstrap CI is [0.100, 0.450]. The mechanical gate uses point estimates (per the pre-registration), but always report the interval; rule 2's basis is by contrast very tight (Greedy KxMinFrac CI [0.040, 0.040] vs Random ~0.79).
    - **`evaluate_competence_gate.py` was frozen BEFORE Track A ran.** Pre-registering four rules is not the same as fixing their implementation, so the free parameters are settled in-file: `half = T//2`; **SuffFail(T/2) is a SUFFIX `[half,T)` but KxMinFrac(T/2) is a PREFIX `[0,half)`** (the easiest thing to get silently wrong); "decreasing" compares exactly two points; strict `<`/`>` so ties fail; 1/K from the environment's K; missing/duplicate/extra seeds are a hard ERROR, never a silent subset; trajectory length ≠ env horizon is a hard ERROR. Rule 1's non-novel-churn clause is deliberately **NOT mechanized** (a threshold invented there would be the post-hoc freedom the file exists to prevent) — churn is computed, reported, and flagged for human reading. Paired bootstrap is uncertainty only and never overrides. `--selftest` validates discriminating power against synthetic fixtures (Thompson passes all four, Random fails rule 2, Greedy fails rule 1, Oracle fails rule 2 as a single-arm policy). **Do not edit this file now that data exists.**
    - **Order is frozen and gated**: manifest check → smoke (Easy/Hard × bare/chat × 3 seeds, protocol correctness only) → `A0_BARE` → `A0_CHAT` → gate verdict → only then B1 α∈{−4,0,+4}. The competence gate is judged on **reference-bare ONLY** (the NMD mask is bare-string; chat is the literature comparator). If neither bare condition passes, an α sweep is **failure-mode characterization** — the words capability-effect / rescue / improvement are not available.
    - **GATE VERDICT (2026-08-04, N=20, frozen): Easy-bare PASS (4/4 rules), Hard-bare FAIL (rule 1 only).** Easy-bare is therefore the B1 competence anchor and α there may be discussed as moving a competent policy; **Hard-bare α is failure-mode characterization only** — the forbidden words above apply to hard, not to easy. Numbers: Easy SuffFail 0.150 vs Greedy 0.250, KxMinFrac 0.046, adherence 0.905, late OptFrac 0.739. Hard SuffFail **0.450 vs Greedy 0.350** (the only failing rule), KxMinFrac 0.030, adherence 0.801, late OptFrac 0.471.
      - **Hard's failure is single-point and diagnosable: exploration COVERAGE, not value integration.** 10/20 episodes never tried all 5 arms (3 pulled only ONE arm for all 100 rounds), 7/20 never pulled the best arm at all. But *conditional on having discovered the best arm*, Hard's late OptFrac is 0.725 vs Easy's 0.739 — indistinguishable — and rule 3 (adherence 0.801) passes. So the model reads its own data correctly; it just does not go get the data. This is the same mechanism pv5 hit (given equalized trial counts the model tracks the empirical-best set; what is missing is an uncertainty bonus), now reproduced in a clean reference environment.
      - **Hard's rule-1 gap is inside the noise: paired bootstrap `suff_fail_vs_greedy = +0.100, CI [−0.150, +0.350]` straddles 0.** The gate judges point estimates per the pre-registration, so FAIL stands and must not be re-judged — but the correct wording is "**did not pass the gate**", NOT "significantly worse than Greedy". Always report the interval alongside.

Hard-chat had not been run as of 2026-08-04, so the interface contrast is incomplete.
    - **Hard-chat (run 2026-08-05) completes the interface 2×2 and confirms the mechanism split: chat RELOCATES the failure, it does not rescue it.** Hard-chat fails rule 1 only, at *exactly* Hard-bare's 0.450 — same single failing rule, same value. Chat fixes coverage on both environments (Hard arms_discovered 3.35→5.00/5) but collapses convergence (Hard adherence 0.801→0.396; Easy 0.905→0.559). So neither interface gets both halves: bare converges without exploring, chat explores without converging. Do NOT read Easy-chat's 4/4 pass as "chat is better" — it is not gate-eligible and it passes by the opposite mechanism.
    - **B1 RESULT, Easy-bare both-stage α=±4 (N=20 paired seeds, 2026-08-05): +4 DAMAGES the policy; −4 is behaviourally null.** Full tables + interpretation live in `AdaDopamine.md` §3.2.5 — cite there. The load-bearing decomposition: **+4's damage is to PERSISTENCE, not to discovery.** 96.6% of its extra switching lands on already-tried arms (`nonnovel_churn_rate` .059→.159, p=.0014) and 99.6% of its extra non-greedy rounds occur *after* the best arm was already found; `best_never_tried` stays 0/20 and `arms_discovered` barely moves. Adherence .905→.672 (p=.0064), late OptFrac .739→.579, regret 14.8→21.4. **This is why "+α = more exploration" is the wrong reading** — the model is not going and getting new information, it is failing to hold onto what it already found. −4 is null on every outcome metric but NOT inert: it shifts the candidate distribution and the rationale text, so report it as "behaviourally null, distributionally active", never as "no effect".
      - **No inverted-U here — only a right arm.** Three α points on a ceiling-adjacent baseline cannot show a peak. Easy-bare α=0 is already near this task's ceiling (late OptFrac .739, adherence .905, `best_never_tried` 0/20), leaving −α no headroom — structurally the same baseline-ceiling artifact as Qwen's MMLU betting cell. **The dilemma this creates is real and unresolved:** the environment that passed the gate has no improvement room; the one with room (Hard) did not pass.

It fails closed: `attest()` derives each cell's expected `steering_fires` from that cell's OWN config via `expected_fires(alpha, scope, k, horizon)` and raises `SystemExit` on mismatch, so behaviour is never read off a cell whose intervention is unverified. Attestation runs for EVERY `--part`, not just `--part attest` (a single-part call is the normal way to pull one table and must not bypass the check); `--skip-attest` exists for debugging only and prints a warning.   - **pv7 (2026-08-05) — the interface rebuild that superseded pv6. Itself superseded by pv8/pv9, but it defines the token/anchor invariants and the Stage-1/Stage-2 split every later protocol inherits.** pv6 is NOT void: it stays citable as a **boundary finding** (what α does on an interface that truncates the rationale, contradicts itself at Stage 2, drifts the option display, and leaves a label prior uncontrolled). But its α numbers cannot be pooled with pv7's, and pv7 needs its OWN α=0 competence anchor before any α claim. Files: `bandit_pv7.py` (prompts/state, pure — no model), `test_bandit_pv7.py`, `freeze_pv7_states.py` + `bandit_pv7_frozen_states.json`, `eval_pv7_frozen_states.py`. pv6 files are byte-unchanged.
    - **Four pv6 defects it fixes, all measured not assumed:** (1) **rationale truncation** — 74–93% of pv6 rationales end mid-sentence at the 64-token cap and only 224/2000 reach `## Step 2` (9 finish it), so what Stage 2 received was mostly a restatement of the state table with the explore/exploit weighing cut off; (2) **Stage 2 self-contradiction** — pv6 rebuilds `state + _RATIONALE_INSTRUCTION`, so "Do not state a final choice yet" is still ~40 tokens above the anchor that demands a choice; (3) **option-display drift** — pv6's TRIED/UNTRIED split moves arms as they get tried, so **24/120 frozen slots (slot 96/120 = 80.0%, dedup 87/107 = 81.3%)** show an order differing from the run's fixed `arm_order`; pv7's single OPTIONS table is 100%; (4) **label prior** — pv6 round-1 picks "Button A" ~95% of the time by LABEL while display position spreads {1:10, 2:4, 3:5, 4:1}, i.e. a label prior, NOT a position bias, so the counterbalanced seed bank does not neutralize it (it balances position). Handle by statistical control (label fixed effects, `α × Button A` interaction); candidate-prior calibration is a scaffold and belongs in an ablation only.
    - **Anchor design is the load-bearing change, and it is about RSN alignment, not aesthetics.** Both stages now end in ONE literal ASCII space: `Evidence: ` (Stage 1) and `Choose Button: ` (Stage 2). For the Llama-3.1 tokenizer that tail is **token 220**, the same decision-bottleneck token the RSN mask was extracted at (`Answer: ` in the MMLU template). pv6 instead ended Stage 2 at `Choice: Button` → ` Button` (6739) and Stage 1 at the period of "…final choice yet." — an asymmetry, not an inert site. **Correction to an earlier reading: injecting at that period is NOT ineffective** — on round 0, where the state is byte-identical across cells, `both(+4)` changed the rationale in 20/20 seeds (`both(−4)`: 11/20). A period's hidden state carries the whole context; the real defect was that the two stages anchored at semantically different places.
    - **Candidates are BARE `A`/`B`/`C`/`D`/`E` = token 32/33/34/35/36** (pv6 used `' A'` = 362). This is forced by the trailing space and is itself a reason pv7 is a new protocol. **The concatenation must happen at the ID level.** `llms.py:527-537` (`regenerate_logits_teacher_forcing`) tokenizes prompt and answer separately and concatenates id lists, giving `[…, 220, 32]` — correct. Building the sequence as the STRING `prompt + candidate` instead lets BPE merge `220 + A` back into `' A'`: the sequence is one token SHORTER, the scored token becomes 362, and the injection site silently slides to the colon (25). It does not raise. `bandit_pv7.audit_id_level_continuation()` fails closed on all of this and is the negative control.
    - **Two silent-corruption hazards worth knowing:** `.rstrip()` on a pv7 prompt moves the tail token from 220 to `:` (25) — which is why "the trailing space must survive" is an assertion, not a comment; and a stray DOUBLE space is a single token 256, not `220,220`, so the rationale (never the prompt) is `rstrip`ped before the anchor is appended.
    - **Anchor collision is OBSERVED, never cleaned (settled 2026-08-05).** pv7 invites the policy to name a button, so the model can emit `Choose Button:` itself, putting two anchors in the Stage 2 prompt. The injection site is still correct (verified: tail stays `[…,25,220]`, boundary `[220,32]`), but a rationale that already committed gives Stage 2 a self-cue that would inflate the action-follows-rationale readout. `bandit_pv7.rationale_format_flags()` records `rationale_contains_action_anchor` / `rationale_contains_evidence_anchor` / `empty_rationale` / `starts_with_redundant_evidence` and **nothing is dropped** — report the metric overall AND on the collision-free subset, because deleting collisions creates a selection bias. A materially non-zero rate disqualifies the PROMPT VERSION; it is not repaired in post-processing. Do NOT pre-emptively switch to `Selection: ` (also token 220) — that trades one possible collision for another and adds a variable before any collision rate has been measured. Once trajectories run, the anchor is frozen.
    - **Frozen-state bank: 120 slots, 107 unique histories — two analysis units, do not mix.** 20 seeds × 6 state types (round_1 / first_partial_tried_untried / after_first_positive_reward / after_first_two_consecutive_zero_rewards / round_50 / round_100), sampled from stored α=0 pv6 trajectories. The 13 duplicates are all `first_partial_tried_untried` coinciding with an event type. **(a)** the six per-type tables keep all 20 slots each (one history answers a different diagnostic question under each type); **(b)** any POOLED statistic deduplicates on `state_fingerprint` (a verified bijection with `(seed, history, arm_order)`) and reports **n=107, not 120**. A bare percentage with no denominator is a reporting bug — this is exactly how 80.0% and 81.3% can both be right for the same fact.
    - **`eval_pv7_frozen_states.py` = Phase 3, a paired INTERFACE comparison (not a wording ablation).** Three arms on the same frozen states: `p0_pv6_interface` (the REAL pv6 path — its prompt, sanitizer, `Choice: Button` anchor and `' A'` candidates), `p1_structural`, `p2_light_hint` (P1 + one weak-evidence sentence). **P0 must never be "aligned" to token 220 or bare candidates** — that would measure wording instead of the interface change actually being made. Consequence to state whenever citing them: margin / norm_entropy differences between P0 and P1/P2 **include** the anchor and candidate-tokenization delta. Held constant across arms: the frozen state, `temperature=0`, `max_new_tokens=64` (module constants, deliberately not per-arm). Validity is judged against each arm's OWN protocol — requiring pv6 to end on 220 would report a spurious failure for an invariant it never claimed. Cost is reported per stage. `--dry_run` needs no GPU (prompt construction + validity only); `--model_dir` defaults to the HF repo id `meta-llama/Llama-3.1-8B-Instruct`, matching `run_bandit_reference.sh:119` — there is no filesystem model dir. ~360 generations + 360 batched scorings.
    - **Selection rule (frozen): choose the prompt on validity / evidence grounding / rationale completion / cost ONLY, never on true-best outcome.** The frozen states were sampled from α=0 pv6 trajectories, so selecting by reward fits the prompt to its own history.
    - **Grounding metrics separate FACT from EPISTEMICS.** `any_grounding_error` covers only mechanically checkable errors (fabricated reward/trial counts, wrong empirical rate, an UNTRIED arm described as observed, and at Round 1 any reward claim at all — nothing has been observed yet, which is why Round-1 hallucination is reported on its own 20-state denominator). Whether 1 trial may be called "well-supported" is a judgement, so `support_overclaim` is recorded DESCRIPTIVELY and stays out of `any_grounding_error`. Grounding is computed on BOTH `raw` (primary: what the model generated) and `clean` (what Stage 2 saw) — for P0 these differ, since pv6's sanitizer deletes whole `Choice:` lines, and a clean-only reading understates the generation tendency.
    - **`policy_*` fields are HEURISTIC post-hoc descriptors, not pre-registered outcomes or gate metrics.** `policy_target_source ∈ {policy_segment, full_text_fallback, none}`: the headline action-follows-policy uses `policy_segment` WITH a clear explore/exploit stance, because the fallback picks the last button named anywhere and will happily return a button mentioned in the *Evidence* half (verified: "Evidence: Button C looks best but Button D untried; Policy: explore Button D" → segment correctly yields D, fallback would yield C). With K=4 there are 3 non-leader arms, so a permissive rule would let any non-greedy sample count as following the named competitor and alignment would decay into a restatement of the non-greedy rate.
        - **`one_shot_zero_revisit` has TWO readouts and the binary one is near-saturated.** Denominator (pre-registered): episodes where forced init produced at least one `0/1` arm AND at least one adaptive SAMPLE remained. The frozen **binary** reads **17/20 = .85** on PV10-A α=0 — too close to ceiling to show improvement — so the PRIMARY readout is the **fraction** `revisited 0/1 arms / all 0/1 arms`, per-episode then seed-paired, which reads **.617** on the same data and has real headroom (per-episode 0/1-arm counts range 1–4).
